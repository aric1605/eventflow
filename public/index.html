Distributed Event Processing Architecture

EventFlow is an enterprise-grade asynchronous event ingestion and processing engine built with Fastify, PostgreSQL (Neon), and Redis Streams (Upstash).

Delivery Semantics & Guarantees

  • AT-LEAST-ONCE Delivery: Events are guaranteed to be executed at least once. If a worker crashes mid-computation or an unacknowledged timeout occurs, the recovery sweeper reclaims the message.
  • IDEMPOTENT Processing: Side effects happen effectively once because of atomic row-level claim locking (UPDATE events ... WHERE (status IN ('queued','retrying') OR stale) FOR UPDATE SKIP LOCKED). Duplicate stream deliveries are acknowledged and skipped without re-running handlers.
  • NO Ordering Guarantee: To achieve high concurrent throughput and resilience across distributed worker instances, event execution order across distinct events is explicitly not guaranteed.

Lifecycle State Machine

received (persisted in Postgres) → queued (published to Redis Stream events:main) → processing (atomic claim by worker) → succeeded (attempt recorded, result persisted, stream ACK) OR retrying (exponential backoff with full jitter scheduled) OR dead (persisted to DLQ after exhausting max attempts or permanent error).

Free-Tier Engineering Considerations

  • Upstash Redis Command Quota: Workers use adaptive exponential polling (500ms doubling to 60s) rather than tight loops or blocking commands, conserving commands while idling. Ingestion invokes in-process worker.wake() for instantaneous processing of active bursts.
  • Neon PostgreSQL Cold Starts: Connection pooling with configured timeouts and a 3-stage exponential connection retry policy handles serverless database wakeups gracefully.
  • Render Sleep & Crash Recovery: When free compute sleeps or redeploys, in-flight jobs are safely reclaimed upon waking via visibility timeout sweeper (XAUTOCLAIM).
